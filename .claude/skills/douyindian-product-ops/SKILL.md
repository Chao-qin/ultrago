# 抖店商品操作

这是抖店商家后台（`https://fxg.jinritemai.com`）单商品操作的唯一 skill。它合并了商品生命周期、表单字段路由、逐字段填写手册和真实踩坑记录。

## 0. 强制入口与规则优先级

**执行抖店任务前必须先完整读取本文件。** 不得只凭 skill description、旧对话摘要、页面能否提交或平台默认值开始操作。所有原先分散在表单手册和 field notes 中的规则均已在本文件内；本文件是唯一权威入口。

### 规则优先级

1. 用户明确要求与明确提供的真实商品数据。
2. 抖店当前页面的真实标签、必填状态、错误信息和上传结果。
3. 本文件的安全红线、数据完整性规则和验证要求。
4. 页面黄色提升建议或平台推荐项。

风险项先记录并回显给用户。来源数据中的关键词、品牌、授权、资质或图片风险不构成填写前停止条件：先完整填写并执行“填写检查”；仅页面真实红色错误、必填缺失、数据不一致或未知异常才阻断最终提交。

### 四个发布硬门

发布、编辑保存、下架、上架、删除前必须全部满足：

- 已完成本文件的前置检查和字段填写检查。
- 没有红色错误、必填缺失、数据不一致、未关闭的阻塞弹窗或未解释的页面异常。
- 价格、库存、品牌、授权、资质、生产企业和图片默认来自用户或商品数据，未经用户确认不得改写、猜测、截断或补造；平台生成图片只有用户明确同意且页面允许时才是例外。
- 平台自身出现红色错误或阻断时，停止在最终提交前；可以保留已填表单或保存草稿，不得擅自改写、删除或伪造商品数据来规避平台校验。

“填写检查”显示黄色提升建议时，可以继续，但必须在结果中回报。质量分低于页面明确的硬性阈值、错误提示有红色项目、重要必填属性未完成时，不得继续发布。

## 1. 快速工具路由

本文件使用当前 Browser MCP 客户端暴露的 `browser_*` 工具名，例如 `browser_upload_file`、`browser_type_text`。后端 `registerTool` 源码内部可能使用不带前缀的注册名（如 `upload_file`、`type_text`）；执行时以当前客户端实际工具列表为准，不从源码臆造工具名，也不把内部注册名当作可调用名称。

| 操作 | 正确工具 | 禁止替代 |
|---|---|---|
| 上传主图、详情图、规格图 | `browser_upload_file(ref, url=...)` 或 `browser_upload_file(ref, localPath=...)` | 点击上传文本、`eval` 注入 File、`drag` 上传 |
| 填文本输入框 | `browser_type_text` | `eval` 直接设 value |
| 原生下拉 | `browser_select_option` | 把自定义下拉当原生 select |
| 抖店自定义下拉、多选 | `browser_pick_option` | 逐个盲点、猜 DOM 选择器 |
| 点击控件 | `browser_click` 或 `browser_click_text` | `eval` 点击；最终风险动作还需 `confirm:true` |
| 规格动态输入失焦 | `browser_press_key`，通常 `Tab` | 手动猜测下一个输入框已出现 |
| 滚动 | `browser_scroll` | `eval scrollTo` |
| 看完整页面 | `browser_analyze_page` | 只看截图后猜测 |
| 轻量读取控件 | `browser_snapshot` | 使用过期 ref |
| 等待 SPA 或异步任务 | `browser_wait_for` / `browser_wait_for_event` | 无验证地连续点击 |
| 确认网络落点 | `browser_read_network` | 只看按钮变色或文字 |

每个动作都遵循 `perceive → act → verify`。工具返回的 `↳ changed:` 必须阅读；出现 `⚠ Verify gate` 或新错误、弹窗、导航后，下一步前必须重新 `snapshot` 或 `analyze_page`。ref 只对最近一次 snapshot 有效。

## 2. 前置 P0 自检（起步前检查）

开始填写前先验证：

| 前置 | 快速验证 | 不满足时 |
|---|---|---|
| 已登录抖店会话 | 页面不是登录墙、扫码页 | 停止并让用户登录，不代填账号密码 |
| 页面已水合 | `snapshot` 有真实类目/表单内容 | `wait_for` 已知元素；不要在骨架页操作 |
| 图片可上传 | 用第一张主图做一次 `browser_upload_file` 冒烟，出现缩略图和 DOM 变化 | 按图片失败路径处理；不要批量盲传 |
| 类目可定位 | 搜索结果能选到目标叶子类目 | 停止并让用户确认三级类目 |
| 品牌可选 | 抖店品牌搜索能命中 | 搜不到选“无品牌”并告知；禁止伪造品牌 |
| 白底图/资质 | 数据有真实素材时可上传 | 缺失时保持为空并记录，不作为填写、保存或发布阻断条件 |
| 目标商品明确 | 新建，或已有商品名/ID可定位 | 不猜目标，不批量操作 |

如果当前已有未保存表单，离开时可能出现原生确认弹窗；从空白页或新标签进入创建页，避免清空用户已填内容。发布页禁止 reload，reload 可能清空标题、属性、图片、规格和 SKU。

## 3. 页面进入与状态模型

目标 URL：`https://fxg.jinritemai.com/ffa/g/create`

进入成功的信号是 `snapshot` 看到类目搜索/选择区域或“基础信息”。看到登录页、空白骨架或未知错误时停止处理。

### 三种进入路径

1. 直接导航到目标 URL。
2. 在后台 `snapshot` 找“商品”→“商品管理”→“发布商品”，进入类目选择后跳转表单。
3. 编辑已有商品时使用页面提供的编辑入口或 `create?product_id=<商品ID>`；编辑模式下部分类目/属性可能不可改，以页面为准。

### 0.3 从零到发布的完整操作流程示例

1. 导航到发布页，确认看到类目搜索框。
2. 搜索商品数据中的类目关键词，选择完全匹配的叶子类目，回读基础信息区域。
3. 填标题，回读标题和字符数。
4. 按 `RefPid` 填所有 `ImportantAttr`，再填实际存在的选填属性。
5. 主图先传第一张做冒烟，再按顺序传完并确认缩略图。
6. 详情图与主图相同时用“从主图填入”，否则逐张上传并确认数量。
7. 创建带图的第一规格项（通常颜色），按动态输入规则填完所有值。
8. 逐个规格值上传对应 `ImgUrl`，确认名称与图片对应。
9. 创建其它规格项（例如高度）并填值；若单值规格被平台拒绝，停止询问。
10. 等待 SKU 表自动生成，确认行数等于笛卡尔积。
11. 逐行按 `SkuSpec` 填价格、库存、商家编码和启用状态，虚拟滚动后重 snapshot。
12. 选择真实运费模板并回读。
13. 点击“填写检查”，修复所有红色错误，黄色建议记录但不隐藏。
14. 发布前回显动作和关键字段，成功后确认成功页、商品 ID和待审核状态。

商品状态流转：

```text
[草稿] --发布商品/提交审核--> [待审核] --审核通过--> [出售中/已上架]
   ^                              |审核不通过
   |保存草稿                       v
 (新建页)                       [审核未通过]

[出售中] --下架--> [仓库中] --上架--> [待审核或出售中]
[仓库中] --删除--> [已删除]
```

- 删除前必须先下架到仓库中；删除不可逆。
- 下架和上架是可逆操作
- 已上架商品改标题、类目、主图、价格等核心信息通常会重新审核；轻字段是否即时生效以页面提示为准。
- “商品提交成功”只表示进入审核流程，不表示审核通过或已经对外销售。

## 4. 数据对象与表单分区

典型商品数据对象：

```text
GoodsID
BaseInfo.CategoryId / CategoryName / Title / MerchantCode
BaseInfo.Attr.ImportantAttr[] / OtherAttr[] / SourceAttr[] / AttrValues{}
CommodityImage.ConfigList[]       主图 / 白底图
DetailImage.ConfigList[]          详情图
PriceAndStock.SkuProperties[]     规格项、规格值、规格图
PriceAndStock.Skus[]              SKU 价格、库存、OuterID、启用状态
PriceAndStock.SpecRule
Qualification.ConfigList[]        资质
```

| 表单分区 | 数据来源 | 关键规则 |
|---|---|---|
| 类目/标题 | `BaseInfo.CategoryName` / `Title` | 选到完全匹配的叶子类目；标题不超过60字符 |
| 属性 | `ImportantAttr`、`OtherAttr`、`AttrValues` | 先必填后选填；按 `RefPid` join，禁止臆造 |
| 商品图文 | `CommodityImage` / `DetailImage` | 主图、白底图、详情图分开处理和验证 |
| 规格库存 | `SkuProperties` / `Skus` | 规格值先完整建立，再按笛卡尔积核对 SKU |
| 资质 | `Qualification` | 有真实资质时才上传；缺失时保持为空并记录 |
| 商品级编码 | `BaseInfo.MerchantCode` | 与 SKU 级 `Skus[].OuterID` 分开填写和校验 |
| 服务履约 | 不在数据对象内 | 使用页面默认或询问用户，不猜运费/售后承诺 |

`SourceAttr` 只作候选参考，不直接自动进表单。若 `AttrValues` 未覆盖某个必填字段，可把 `SourceAttr` 作为候选值展示给用户；用户确认且页面选项匹配后才能填写。字段名称来自属性配置，通常字段值来自 `AttrValues[RefPid].Label`；数据标签和页面标签不一致时按页面包含匹配，匹配不到就停下。

### 权威性分层

| 内容 | 权威来源 | 冲突处理 |
|---|---|---|
| 字段清单、必填标记、图片数量/大小、规格结构、SKU组合、属性值 | 商品数据对象与抖店返回字段配置（`IsRequired`、`MinInput`、`MaxInput`、`SkuProperties`、`Label`） | 以数据配置和当前页面校验为准 |
| 分区名称、按钮文案、控件位置、交互顺序 | 当前抖店页面 | 以最新 `snapshot`/`analyze_page` 为准 |

页面文案比数据 `Label` 更完整时按包含/搜索匹配；不能为了字符串一致而选择近似错误值。

## 5. 字段填写路由

| 字段信号 | 操作 |
|---|---|
| `<input>`、`<textarea>`、`contenteditable` | `browser_type_text`，回读 value |
| 原生 `<select>` | `browser_select_option` |
| combobox、箭头、自定义 Select | 先 click 触发 → 新 snapshot → `browser_pick_option` |
| MultiSelect（由 `ChooseMaxNum` 限制） | 触发弹层 → 重 snapshot → 逐项 `browser_pick_option`，遵守最大数量 |
| 搜索型属性 `IsSupportSearch=true` | 先输入搜索词，再选真实结果 |
| file upload | snapshot 找 `<input type=file>` ref，直接 `browser_upload_file` |
| 动态规格输入组 | type → `Tab` 触发 blur → 重 snapshot → 重复 |

属性的 `PropInputType` 路由为：`Select` 用自定义下拉，`MultiSelect` 逐项多选，`Input`（常见 `DiyType=1`）用文本输入；不能把自定义 Select 当作原生 `<select>`。

品牌规则：先搜索商品数据中的品牌；抖店店铺品牌库不存在时选“无品牌”并告知。禁止把1688品牌名直接当作抖店品牌，也禁止伪造品牌。

自定义下拉失败路径：

1. `browser_pick_option` 只尝试一次。
2. `analyze_page` 确认弹层和真实控件位置。
3. 在 `BCP_EVAL=on` 且普通工具确实无法操作时，才用 `browser_eval` 作为最后兜底；执行后必须 snapshot 验证选中值。
4. 仍失败则停止并回报，不反复盲点。

## 6. 基础信息填写

按以下顺序：类目 → 标题 → `ImportantAttr` → `OtherAttr` 中实际有值的项。

- 类目必须选到叶子，回读面包屑与数据 `CategoryName` 一致。
- 标题回读一致且 ≤60 字；超长不得静默改写，需告知用户。
- 每个 `ImportantAttr` 必须有页面选中值，页面无红色必填提示后才能进入下一分区。
- `OtherAttr` 中只有在 `AttrValues` 出现的字段才填，未提供的保持空白。
- 若存在 `BaseInfo.MerchantCode`，必须在商品级编码字段填写并回读；它不等同于 SKU 的 `OuterID`。
- 自定义文本输入按数据原值填写；格式校验失败时回报，不用近似值替代。

### 字段速查示例

不同类目会返回不同 `RefPid`，以下是典型映射，仅用于识别字段类型，不得跨类目硬编码：

| RefPid | 字段 | 必填 | 常见 UI | 处理 |
|---|---|---:|---|---|
| 1687 | 品牌 | 是 | Select+Search | 搜索并选中真实品牌；否则“无品牌” |
| 2108 | 玩具类型 | 是 | Select | 自定义下拉选页面值 |
| 3127 | 材质 | 是 | Select | 按页面包含匹配 |
| 2595 | 适用年龄 | 是 | MultiSelect≤5 | 逐项勾选 |
| 4738 | 尺寸 | 是 | Input | 原样输入，格式失败就停 |
| 1880 | 产地 | 否 | Select | 只有数据提供时填写 |
| 2752 | 颜色分类 | 否 | Input/Diy | 按数据逗号串输入 |
| 3171 | 货号 | 否 | Input/Diy | 使用真实货号 |

其余 `OtherAttr`（图案、种类、大小、性别、安全等级、填充物、卡通角色、版本、型号、CCC编号、统一社会信用代码、产品名称等）只在 `AttrValues` 出现时填写。

## 7. 图片与详情图

**所有图片只使用 `browser_upload_file`，禁止素材库、`eval` 注入和 `drag`。** 数据有公网 URL 时优先 `url`；用户本地素材用 `localPath`；单文件 ≤25MB。主图视频超过限制时跳过并回报，视频不是图片上传的替代品。

### 通用上传验证

1. snapshot 取得当前 file input ref。
2. 上传第一张做连通性冒烟。
3. 每张上传后读取 `↳ changed:`，等待页面处理。
4. snapshot 确认正确缩略图；必要时 `analyze_page` 截图。
5. 批量不确定时开启 `browser_set_network_capture`，抽查 `batchupload/upload` 200 响应，之后关闭捕获。
6. 无缩略图或无变化：重试一次；仍失败则回报用户手动上传，不能用 drag 兜底。

上传验证的四个证据层：工具无 error、`↳ changed:` 有元素变化、snapshot 有缩略图、截图确认图片正确。缩略图不显示时才升级到截图和网络捕获，不要仅凭 `browser_upload_file` 返回值声称成功。

上传前通常是隐藏 file input + “+”占位符；如果 file input 不在初始 snapshot，先 hover 或点击非风险的上传区域触发控件，再重新 snapshot；上传成功后应看到 `<img>` 缩略图和删除按钮。批量上传抽查时：开启网络捕获 → 上传 → `browser_read_network` 查找 `batchupload`/`upload` 的 HTTP 200 → 关闭网络捕获。

### 主图

- 按数据 `CommodityImage.ConfigList[主图].List` 顺序上传，首张是封面。
- 页面要求通常为 3–5 张；以当前字段配置和页面校验为准。
- 每张 ≤5MB（若页面限制不同以页面为准）。

### 白底图

- 数据有真实白底图时只上传该图。
- 数据没有且 `MinInput=0` 时先空着，观察页面校验。
- 页面强制要求且无真实素材时停下询问：用户是否提供、是否同意使用平台生成入口、或指定某张主图；禁止擅自拿主图冒充白底图。

### 详情图

详情区通常是富文本编辑器，机制不同于普通 file input：

- 详情图等于主图或是主图子集：优先点击“从主图填入”，再 snapshot 验证缩略图。
- 详情图不同：寻找详情区的添加图片/file input，按数据数组顺序逐张上传并验证。
- 可在富文本编辑器中调整顺序、删除图片、插入文字，但只能使用用户提供的真实素材。
- 详情图数量与数据 `DetailImage.ConfigList[].List` 一致；数据为 0 时按页面实际要求处理。

### 7.1 图片源数据解析硬门

在判断“规格图缺失”“规格图无法对应”或准备使用主图替代前，必须先回查商品源数据，不能只根据抖店当前页面的主图列表或截图推断：

1. 不得根据目录名猜测来源。扫描 `products/` 的每个候选目录，在其 `raw.json`、`preprocessed.json` 和 `final.json` 中分别用已有的 `SourceID`、`GoodsID` 和标题做精确匹配：`raw.json` 读取顶层 `SourceID`/`GoodsID` 与 `BaseInfo.Title`，预处理或最终文件读取其保留的商品 ID 与顶层 `title`。记录每个候选目录的匹配字段和文件证据；抖店商品 ID 不等同于 1688 `SourceID`，不能用抖店 ID 或目录名推断来源。
2. 若没有候选目录匹配，停止并询问用户提供 `SourceID`、`GoodsID` 或准确标题；若多个候选目录匹配，停止并列出各候选目录及匹配证据，请用户明确选择。只有恰好一个候选目录匹配后才能读取其中的数据文件。
3. 按文件结构读取规格图字段并建立 `规格值 -> 图片 URL` 映射，保留原始顺序：`raw.json` 使用 `PriceAndStock.SkuProperties[].Values[].ImgUrl`；`preprocessed.json` 使用顶层 `skuProperties[].Values[].ImgUrl`；`final.json` 使用顶层 `skuProperties[].values[].image`。这些字段是规格图权威来源，优先级高于 `CommodityImage` 主图和 `DetailImage` 详情图。
4. 先输出完整度：规格值总数、带 `ImgUrl` 数量、缺失名称和每个规格值的图片 URL。只要源数据存在 `ImgUrl`，就不得报告“没有规格图”。
5. 页面有规格值但源数据缺 `ImgUrl` 时，才标记为源数据缺图并停止询问；不得用主图、详情图或其他 SKU 图片顶替。源数据存在而页面缩略图为空时，应继续按映射上传并验证页面结果。
6. 上传完成后按同一映射逐项回读缩略图；规格图的判断必须同时有源数据证据和页面缩略图证据。

## 8. 规格、规格图与 SKU

心智模型：

```text
规格项（维度，如颜色、高度）
  └─ 规格值（选项）
       └─ 规格图（绑定规格值，不绑定单个 SKU）
SKU = 各规格项各取一个值的笛卡尔积
```

### 建规格

1. 点“添加规格项”。有 `ImgUrl` 的规格项（通常颜色）放第一位。
2. 规格值是动态输入组：输入一个值后必须 `Tab` 失焦，等待下一个输入组出现，再继续。
3. 全部规格值出现后，重新 snapshot 统计数量；不要凭看到一部分就认为填完。
4. 若页面不允许只有一个值的规格项，停止并回报，不擅自删除或改变数据维度。

### 规格图

- 规格图绑定规格值，不绑定 SKU；颜色 × 高度的多个 SKU 可共用颜色规格图。
- 只为有 `ImgUrl` 的规格项上传，通常仅主规格允许挂图。
- 每个规格值使用自己的 `ImgUrl`，逐值上传，严禁用主图或详情图顶替。
- 上传后逐值确认缩略图与颜色/规格名对应；批量后抽查网络上传 200。

### SKU 表

- 等规格值完整后等待页面自动生成 SKU，不手动添加额外行。
- 预期行数 = 所有规格值数量的笛卡尔积。
- 按 `SkuSpec` 定位对应行，再填价格、库存、商家编码、条形码和启用状态。
- SKU 表可能虚拟滚动：每滚一屏都要重 snapshot，旧 ref 失效；抽查首、中、尾和最高/最低价行。
- `SkuState=true` 才启用；`Price=0` 表示价格走 SKU 级，不要当作零元商品。
- 价格必须遵循用户明确策略。若商品数据已有 `Skus[].Price` 或预处理后的最终售价，必须原样使用；`采购价` 永远不是销售价，不能直接填入售价字段。只有在 SKU 价格缺失、用户未指定其它策略且数据明确提供“采购价 +10”策略时，才可按该策略计算。遇到币种、阶梯价或异常数据先询问。
- 库存必须保留真实数据。平台上限冲突时**停止并询问用户**选择真实库存、分拆库存或保存草稿；不得自动截断为平台上限、填99999或清零。

规格图对应规格值而不是 SKU。若颜色有 19 个值、高度只有 1 个值，SKU 是 `19 × 1 = 19` 行；高度没有 `ImgUrl` 时不传图。若规格规则不允许单值维度，以页面错误为准停止，不自行删除该维度。

## 9. 服务与履约

商品数据通常不含运费、发货和售后字段：

- 运费模板优先选择页面内置“全国可寄，非偏远地区包邮”，但若用户或页面显示其他真实模板，以页面和用户指定为准。
- 发货模式、库存扣减方式、发货时效用默认或按用户说明；不确定时询问。
- 售后政策按实际商品和类目默认；不能擅自增加或减少承诺。
- 遇“关联货品”“存储模板”等弹窗，先关闭或 Escape，重新 snapshot 后再继续。

## 10. 资质、授权与真实性红线

报关单、质检报告、CCC证书、生产企业、统一社会信用代码、IP授权、品牌和资质图片只使用用户提供或商品数据中的真实资料；缺失时保持为空并记录。

授权、IP、品牌和资质字段仅作为商品字段或风险记录，不能单独阻断采集、预处理、抖店填写或保存草稿。若抖店页面在“填写检查”或提交前将其显示为红色必填/阻断错误，则停止在最终提交前并回显该页面错误；不得为满足提示而伪造或替代资料。

- 空资质栏位不代表可以伪造填充。
- 只上传确实适用且真实的资质；未做进口就不上传报关单，未声明相关卖点就不上传无关认证或质检材料。
- 生产企业名称用店铺名替代真实生产企业

## 11. 填写检查与落点前清单

所有字段完成后必须点击“填写检查”，等待 1–3 秒并重 snapshot。

### 必须阻断的红色问题

- 错误提示 Tab 有项目。
- 必填字段未填或格式错误。
- 类目不是目标叶子类目。
- 标题超过60字符或回读不一致。
- `ImportantAttr` 未全部有值。
- 主图数量、详情图数量、规格图绑定或 SKU 行数不满足页面/数据要求。
- 价格、库存、编码与商品数据不一致。
- 商品级 `BaseInfo.MerchantCode` 未填写或与回读不一致。
- 页面重要属性进度显示 `x/y` 且 `x < y`，但没有逐项确认剩余项确实是页面配置允许的非必填增强项。
- 运费模板未选择或回读不一致。
- 页面出现未处理的阻塞弹窗、登录失效、网络错误或未知异常。
- 抖店“填写检查”或提交前将授权、IP、品牌或资质显示为红色必填/阻断错误。

### 可继续但必须回报的黄色建议

- 页面明确标记为非必填增强项的属性未完成，且已逐项读取页面配置确认可豁免。
- 缺少主图视频但页面未要求为必填。
- 白底图仅属于提升项且页面允许为空。
- 质量分低于推荐分但没有页面硬性阻断。

“黄色”必须由页面真实状态确认；不能把红色错误改名为建议项。

### 手工回读清单

| 项目 | 通过标准 |
|---|---|
| 类目 | 页面叶子类目 == 数据类目 |
| 标题 | 回读一致，≤60 字 |
| 属性 | ImportantAttr 全有值；其它只填真实数据 |
| 商品级编码 | `BaseInfo.MerchantCode` 与页面回读一致，且与 SKU `OuterID` 分开 |
| 主图 | 3–5 张或页面配置范围内，首张正确 |
| 白底图 | 有真实素材、页面允许为空或用户已确认生成方式 |
| 详情图 | 数量和顺序与数据一致 |
| 规格图 | 每个有图规格值都对应正确缩略图 |
| SKU | 行数等于笛卡尔积；价格、库存、编码、启用状态一致 |
| 服务 | 运费模板、发货和售后状态回读一致 |
| 资质 | 有真实素材时内容与商品一致；缺失时保持为空并记录 |

## 12. 生命周期落点与安全确认

### 保存草稿

用户未明确要求发布、有任何存疑、必填未齐、真实素材缺失或平台错误未解决时，默认保存草稿。保存草稿后仍需验证请求和页面提示，不能因为按钮点击成功就声称保存成功。

### 发布/提交审核

最终按钮前必须发送一条明确回显：

```text
即将执行：将「商品名 / 商品ID」提交抖店审核。
关键字段：类目、标题、SKU数量、价格区间、库存、运费模板、商品状态。
已知风险：属性/视频/授权/资质等页面提示。
```

回归场景：`final.json` 标注 IP/品牌风险但 SKU、图片和价格完整时，必须继续创建商品、填写字段、上传素材并执行“填写检查”；不得仅凭风险记录停止。只有页面实际出现红色阻断，或用户未确认最终提交时，才停止在提交前。

### 下架、上架、删除

- 下架：出售中 → 仓库中；回显商品和影响，用户确认后执行。
- 上架：仓库中 → 上架或再次审核；回显商品和状态，用户确认后执行。
- 删除：仅仓库中可删；必须回显“将永久删除商品 X（ID）”，得到明确“确认删除”后执行；不确定时只下架并询问。
- 一次只处理一个明确目标，禁止无差别全选。

## 13. 发布成功页面、发布后验证与审核跟踪

点击发布后：

1. 等待导航或异步请求结束，不在 spinner 状态下猜成功/失败。
2. snapshot/analyze_page 确认“发布成功/商品提交成功”及操作按钮。
3. 记录商品 ID、页面状态、质量分和黄色建议；需要时保存截图归档。
4. 优先点击“返回商品列表”或进入商品管理，确认商品位于“待审核”而不是把成功页直接写成“已上架”。若当前环境不适合离开成功页，明确回报“提交成功，待审核列表未再次核验”。
5. 审核异步，不要空等或反复刷新。用户之后要求查询时：出售中=审核通过；审核未通过=读取原因，按用户指示修改后重新提交。

成功页通常会提供“继续发布”“返回商品列表”“编辑商品”“复制链接”四个操作；缺少成功文字或页面仍在加载/报错时，不得记录为成功。

结果格式：

```json
{
  "operation": "publish|edit|draft|unlist|relist|delete",
  "product": "商品名或 ID",
  "result": "success|failed|needs_review|cancelled_by_guard",
  "after_state": "出售中|仓库中|待审核|草稿箱|已删除|未核验",
  "sku_count": 0,
  "screenshot": "out/<product>-<operation>.png",
  "notes": []
}
```

## 14. 交互恢复与隐藏 UI

每个动作后先读 `↳ changed:`。无变化时最多重试同一动作两次，总计三次；第三次仍无响应，必须 `analyze_page`。

**三次无反应硬规则：** 动作 → 读 changed → 最多重试两次 → 第三次仍无效就 analyze_page。不得把第四次盲点当作恢复策略；分析后仍落到未知页面时 STOP 并回报现状、截图和卡点。

| 现象 | 处理 |
|---|---|
| tooltip | hover 后重新 snapshot/analyze，读提示后移开 |
| popup/级联下拉 | click 触发 → 重 snapshot → pick_option；选项可能 portal 到 DOM 末尾 |
| drawer/modal | 重新 snapshot 取新 ref；关闭后再次 snapshot |
| scrollable 容器 | 用对应 ref 滚动，不滚 window；滚后 ref 失效，必须重 snapshot |
| lazy-load | 滚动、等待、重 snapshot，直到数量凑齐 |
| 空白/骨架/busy | wait_for 页面实质内容，禁止半渲染操作 |
| 自定义 combobox 打不开 | analyze_page 确认位置；普通工具失败后才 eval 兜底；仍失败停止 |
| 上传无缩略图 | 重试一次；仍失败回报手动上传，不用 drag |
| 页面叫法与数据叫法冲突 | 信页面真实标签，但值必须来自真实商品数据 |
| 原生离开确认 | 不尝试接受；从空白页/新标签规避 |

### 通用坑表

| 现象 | 根因/处理 |
|---|---|
| 图片进素材库 | 走错入口；使用 `browser_upload_file` 注入 file input |
| browser_upload_file 返回成功但无缩略图 | trusted user gesture 或渲染失败；重试一次后回报手动 |
| 图床403 | URL失效或强防盗链；换真实 localPath 或回报 |
| 主图视频超25MB | 跳过视频并回报，视频非必填 |
| 白底图卡必填但无素材 | 停止问用户，禁止主图冒充 |
| 规格图错位 | 按规格值逐个使用自己的 ImgUrl，传后抽查 |
| 规格项无法挂图 | 有图规格项放第一位 |
| SKU行数不对 | 补齐动态规格值，行数必须等于笛卡尔积 |
| 价格填错行 | 按 SkuSpec 定位，不能按视觉顺序猜 |
| SKU只显示前几行 | 虚拟滚动；滚后重 snapshot |
| 高度单值规格被合并 | 仍按数据建；平台不允许时回报 |
| 保存草稿掩盖漏填 | 草稿前也必须独立点击“填写检查” |
| 发布后只看成功页 | 记录为“提交成功/待审核”，不可写成审核通过 |

### 2026-07-26 品牌下拉与品牌库

- 1688品牌值不代表抖店店铺品牌库存在。先搜索；不存在选“无品牌”，告知用户，不伪造。
- 自定义 combobox 的 option 可能 portal 到 DOM 末尾，accessibility tree 可见但不可交互。`pick_option` 失败时先 analyze_page，再在 `BCP_EVAL=on` 下用 eval 作为最后兜底，选中后 snapshot 确认字段和错误提示。
- snapshot ref 可能指向外层容器，页面截图是定位依据；不要凭记忆反复点击同一 ref。

### 2026-07-27 图片、检查与发布成功页

- 详情图是富文本编辑器，优先“从主图填入”，不同图片时找详情区 file input；不能把主图机制直接套到详情区。
- `browser_upload_file` 返回不等于服务器上传成功；缩略图是首要证据，批量后可抽查 `batchupload` 200。
- “填写检查”和手工数据校验互补，二者都要做。
- 发布成功页要确认成功文字、操作按钮、商品 ID并截图；提交审核不是审核通过。

### 2026-08-08 本次流程复盘：skill入口、数据真实性和确认门

- 现象：页面最终能提交，但重要属性只有 `4/17`，两个库存超过平台上限时 agent 擅自改成 `10,000,000`，发布前也没有再次回显并请求确认。
- 根因：没有在操作前加载唯一 skill；把平台能否提交误当成 skill 合规；把“早先要求发布”误当成最终确认；没有把库存异常当作真实性冲突处理。
- 固化规则：本文件必须作为唯一入口先读；ImportantAttr 未完成是阻断；库存/价格冲突必须停下询问，不能自动截断、填默认值或清零；最终按钮前必须回显关键字段并等待明确确认；成功页和待审核状态要分开记录。

## 16. 最终回报

回报必须区分：

- `success`：请求成功且页面成功页已验证。
- `needs_review`：已提交审核，但审核尚未通过，或待审核列表未核验。
- `failed`：页面/网络明确失败。

不能把“按钮点击成功”写成“发布成功”，不能把“提交成功”写成“已上架”，不能把“黄色建议”隐藏不报，也不能把未核验的截图或商品状态编成已核验。

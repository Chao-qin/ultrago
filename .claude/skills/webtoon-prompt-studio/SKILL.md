# 竖屏条漫创作台

帮用户连载竖屏条漫。你负责**剧情、设定、分镜和出图提示词**；用户负责出图、挑参考图定稿。长篇连载最容易出问题的是设定漂移：人物性格变了、前面发生的事被忘了、同一个场景前后布局不一样。所以这个 skill 的核心是**所有设定都存在文件里，每一步先读文件再写，写完再把变化记回去**，而不是靠对话上下文记着。

## 每一步怎么做

七个步骤的**输出格式和自检清单**都在 `references/prompt-kit.md`，那是唯一的来源，执行某一步前先读对应的段落。

- 文件开头的「通用规则」对你同样适用。最重要的一条是：只依据文件里的资料创作，需要新增的设定单独列成「新增设定（待确认）」，由用户确认后再写进去。原因是用户要掌控自己的作品，悄悄补上的设定正是后面矛盾的来源。
- 那份文件本来是写给"复制给别的 agent"用的。在这里由你自己按它执行：文件里写"贴故事圣经"的地方，你就去读对应的文件。
- 用户想在别的平台手动用这套流程时，把 `references/prompt-kit.md` 原样给他。

## 作品文件夹

默认放在项目根目录下的 `comics/<作品名>/`（即 `/home/project/agentchrome/comics/<作品名>/`），用户另外指定了位置就用他的。

```
<作品名>/
├── 故事圣经.md          ← ① 产出；时间线、伏笔表每集更新；含「制作参数」
├── 参考图清单.md        ← 人物 / 场景对应的参考图文件和定稿状态
├── 人物/<角色名>.md     ← ② 产出：人物卡 + 外观锚点 + 设定图提示词
├── 场景/<场景名>.md     ← ③ 产出：场景卡 + 设定图提示词
├── 参考图/              ← 用户放定稿图（你不生成、不修改图片）
└── 第01集/
    ├── 大纲.md          ← ④
    ├── 分镜.md          ← ⑤
    ├── 检查.md          ← ⑦
    └── 出图提示词.md    ← ⑥
```

**命名统一**：同一个人物或场景，在卡片文件名、参考图清单、分镜、出图提示词里都用同一个名字。名字对不上，出图时就会把图配错。
- 场景卡**按地点建**（`场景/旧图书馆.md`，卡里同时写白天版和夜晚版光线），因为布局和标志物不随时间变。
- 参考图**按时段定稿**：清单里分成 `旧图书馆-白天`、`旧图书馆-夜` 两行，分镜和提示词引用时也带上时段。用连字符，不用括号。
- 参考图文件名建议用 `<清单名称>-定稿.png`。

`参考图清单.md` 的格式：

```markdown
| 名称 | 类型 | 文件名 | 状态 | 备注 |
|---|---|---|---|---|
| 林夏 | 人物 | 林夏-定稿.png | 定稿 | |
| 旧图书馆-夜 | 场景 | | 待出图 | |
```

写完人物卡或场景卡时，加一行"待出图"。用户说"林夏定稿了，文件叫 xxx.png"时，改成"定稿"并填上文件名。

## 用户说什么 → 做哪一步

| 用户说 | 步骤 | 先读 | 写到 |
|---|---|---|---|
| 开坑 / 新作品 + 点子 | ① 立项 | — | 故事圣经.md、参考图清单.md（空表） |
| 设计某个角色 / 新人物 | ② 人物设定 | 故事圣经 | 人物/<名>.md，清单加一行 |
| 设计某个场景 | ③ 场景设定 | 故事圣经 | 场景/<地点>.md，清单里每个时段各加一行 |
| 写第 N 集 | ④ → ⑤ → ⑦ | 故事圣经、本集相关的人物卡和场景卡、上一集的分镜结尾 | 第NN集/大纲.md、分镜.md、检查.md |
| 出图提示词 / 出第 N 集的图 | ⑥ | 本集分镜、参考图清单、制作参数 | 第NN集/出图提示词.md |
| 检查第 N 集 | ⑦ | 全部设定 + 本集分镜 | 第NN集/检查.md |
| 某角色 / 场景定稿了 | 更新清单 | 参考图清单 | 参考图清单.md |
| 改设定（角色换装、改性格等） | 改对应的卡 | 那张卡 + 故事圣经 | 那张卡；外观变了就把清单状态改回"待出图" |

"写第 N 集"一次跑完大纲、分镜、检查三步，但**在大纲之后停一下**，把分页概要给用户看，确认后再写分镜。大纲错了，后面全部要重写，这是最便宜的纠错点。用户没说这一集要推进什么时，按故事圣经的阶段弧线和伏笔表自己拟定，写进大纲的「主线推进」，同样在这个停顿点请用户确认。

## 步骤之间的关卡

这些关卡存在的原因是：跳过它们产出的东西，要么对不上设定，要么出图时对不上参考图，最后还得返工。

1. **写分镜前**：本集出场的每个人物和场景都要有卡。缺的先提醒用户，按 ② / ③ 补上，不要在分镜里临时编一个人。
2. **出图提示词前**：
   - 本集必须已经跑过 ⑦，并且冲突清单是"无"或者用户已经处理过。先检查再出图，因为出完图才发现剧情错了，代价最大。
   - 本页用到的参考图在清单里要是"定稿"。有没定稿的，照样可以写提示词，但在那一页开头标注「⚠ 缺定稿参考图：xxx」，并在回复里提醒用户。
   - 每页的参考图数量不超过「制作参数」里的上限。
3. **更新故事圣经**：⑦ 产出的「时间线新增」「伏笔状态更新」在用户确认本集没问题后写回故事圣经；「新增设定（待确认）」逐条问过用户再写。

## 回复方式

- 产出都写进文件。回复里只给要点摘要、文件路径，以及下一步可以做什么。
- **提示词类的产出**（设定图提示词、整页出图提示词）同时直接贴在回复里，放在代码块中方便用户复制。这是用户接下来马上要拿去用的东西。
- 发现设定之间有冲突、或用户的要求和已有设定矛盾时，先指出来，问清楚怎么处理再动手。
